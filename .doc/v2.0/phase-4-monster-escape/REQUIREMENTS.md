# P4 — 怪獸逃跑重設計 · REQUIREMENTS

> **狀態：❌ 取消（2026-08-03，產品決定）。** 使用者決定不向孩子呈現任何「逃跑/失去」概念（Prime Directive：不得讓她被警示/施壓）。已實作並測過的逃跑邏輯已移除、不 ship。以下需求與設計保留作為未來若重新考量的紀錄。
>
> 對應 spec §4.3、TASK-03、RC-3。相依：P1。風險：中。

## 背景
舊 `processSpontaneousEscapes` 每日隨機讓 2~5 隻怪獸逃跑，與使用者行為無關（RC-3）→「有練還被罰」的挫折。**經確認此函式目前無任何 UI 呼叫端（dead code）**，故 P4 = 刪除隨機版 + 實作「與遺忘掛勾」的新版並（之後）接上 UI。

## 功能需求
- **FR-1 逃跑與遺忘掛勾**：某關卡（monster id 1..20）內有字「逾期 ≥ 3 天未複習」→ 該關卡怪獸可能逃跑。
- **FR-2 抓回**：完成一次「包含該關卡逾期字」的每日複習 → 怪獸歸位。
- **FR-3 保底**：單日**最多 1 隻**逃跑；**當日已完成複習則當日豁免**（絕不「有練還被罰」）。
- **FR-4 非責備文案**：逃跑訊息把懲罰轉為劇情＋行動指引（spec §7 GATE：tone 需人確認）。

## 非功能需求
- **NFR-1**：排程判定為純函式、注入 now/today，可 Vitest 確定性測試。
- **NFR-2**：不動圖鑑既有資料結構的相容性（`loadLevelProgress` 新欄位有預設）。

## Out of Scope（本 chunk）
- UI 接線（VocabAdventureMap 逃跑/慶祝顯示、複習完成呼叫）＝ TASK-03b，待**文案 tone 經使用者確認後**再做。

## GATE（需使用者）
- 逃跑/抓回**文案 tone**（不得責備）。
- 是否要向孩子顯示「逃跑」概念本身（Prime Directive：不得讓她被警示/施壓）。
